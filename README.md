## 👋 About Zoey

我是 **Zoey Wang**。  
一名聚焦 **体验设计、增长设计、电商业务设计与 AI Native 产品设计** 的设计从业者。

我的经历主要来自两条主线：

- **Alibaba 电商业务设计实践**：长期处理会员体系、商家增长、品牌营销、多触点体验等复杂业务问题
- **AI Native 产品探索与落地**：持续关注 AI Agent、LLM 产品体验、一致性设计与设计知识结构化

这个仓库不是传统意义上的作品集，也不是单个项目的复盘集合。  
它更像是我的一套 **Design Method Library / Design Skill Repository**：

> 从真实业务中提炼问题结构、设计判断逻辑、体验原则与复用框架，最终沉淀为可读、可用、可扩展的 Design Skills。

如果你是招聘方、同行设计师、设计负责人、产品经理，或者正在构建 AI 时代的设计知识系统，这个仓库可以帮助你快速理解：

- 我如何定义复杂设计问题
- 我如何把经验抽象为方法论
- 我如何平衡业务结果、用户体验与系统复用
- 我如何把设计知识进一步转译为可供 AI 使用的结构化资产

## ✨ What this repository represents

这个仓库代表的不是“我做过什么页面”，而是：

- **我如何思考设计问题**
- **我如何提炼设计准则**
- **我如何搭建可复用的方法框架**
- **我如何将业务经验转换为组织资产 / AI 可读资产**

这里的每一份 skill，通常都经过以下抽象过程：

```text
真实业务问题
→ 拆解关键矛盾
→ 提炼设计目标
→ 总结通用原则
→ 建立判断框架
→ 沉淀为可复用 skill
```

因此，这个仓库更适合被理解为：

**A curated collection of reusable design thinking frameworks, built from real-world product work.**

## 🧠 Core Themes

当前仓库中的内容主要围绕 3 个核心主题展开：

| Theme | Focus | What it helps solve |
|---|---|---|
| **Brand Interactive Marketing** | 品牌互动、用户关系推进、转化路径 | 如何把活动/互动营销经验抽象成长期关系经营型设计方法 |
| **Channel Membership Design** | 多触点会员、标准化与个性化平衡 | 如何在复杂渠道和场景下建立稳定的会员设计判断框架 |
| **Lifecycle Membership Design** | 店铺会员、权益表达、留存召回 | 如何系统设计会员从认知、入会到留存与忠诚的完整链路 |

这些主题背后有一个共同点：

> 它们都不是单点 UI 问题，而是同时涉及 **业务目标、用户关系、信息结构、转化机制、长期体验系统** 的复杂设计问题。

## 📚 Skills Overview

### 1. [品牌互动营销 DesignSkill](./品牌互动营销DesignSkill/)

**关键词：** 品牌互动、营销产品、用户关系推进、转化链路、组件化方法  
**适合场景：** 日常互动营销、活动型产品、增长型页面、品牌导向转化设计

这份 skill 关注的不是单次 campaign 创意，而是：

- 如何基于用户关系阶段设计互动体验
- 如何把品牌表达、内容结构、操作转化放进同一套逻辑中
- 如何让营销设计从一次性项目，升级为可复用的系统能力

---

### 2. [电商行业线下渠道会员 Design Skill](./电商行业线下渠道会员Design%20Skill/)

**关键词：** 渠道会员、多场景、多触点、个性化框架、跨渠道一致性  
**适合场景：** 会员体系、入会转化、渠道触点规划、SaaS 商家会员能力设计

这份 skill 聚焦于一个非常典型也非常难的设计问题：

- 场景差异很大，但不能每次都重新设计
- 商家诉求不同，但不能完全失去平台标准化
- 用户阶段不同，但仍要保持体验连续性

它适合体现我在复杂业务约束下做结构化设计决策的能力。

---

### 3. [电商行业商家会员全生命周期 Design Skill](./电商行业商家会员全生命周期DesignSkill/)

**关键词：** 店铺会员、认知建立、权益表达、留存复购、生命周期设计  
**适合场景：** 店铺会员中心、招募转化、权益体系、长期关系经营

这份 skill 更偏向长期关系设计与系统搭建，核心在于：

- 会员不只是一个页面，而是一套持续经营关系的机制
- 用户入会只是开始，后续的理解、使用、激活、复访、召回都需要系统设计
- 多触点表达必须统一，才能形成稳定会员心智

## 🧩 What makes these skills different

和常见的设计文章或项目复盘相比，这个仓库里的 skill 有几个明显特征：

### 1) 去案例化，但不空泛
不依赖单一项目语境，不讲“某一个页面怎么改”，而是提炼为可迁移的方法。

### 2) 去平台化，但保留业务深度
不绑定具体平台规则，但保留电商、会员、营销等真实业务的复杂度。

### 3) 不是灵感集合，而是判断系统
每份 skill 都尽量回答：
- 这个问题怎么定义？
- 设计目标是什么？
- 应该优先解决什么矛盾？
- 如何做结构化判断？
- 如何评估设计是否有效？

### 4) 天然适合 AI 时代的知识表达
这些内容不仅适合人阅读，也适合被进一步转化为：
- design prompts
- AI design assistant skills
- evaluation checklists
- internal knowledge base modules

## 🛠 How to use this repository

你可以从 4 个层面使用它：

### 1. 作为设计方法参考
遇到复杂业务问题时，先看对应 skill 如何定义问题、拆解目标与建立原则。

### 2. 作为设计评审框架
在评审方案前，用 skill 中的原则与 checklist 反向检查是否真正解决问题。

### 3. 作为团队知识库素材
把 skill 中的结构继续拆成：
- design principles
- review checklists
- onboarding docs
- component/system guidance

### 4. 作为 AI 设计知识底座
如果你在做 AI design assistant、design agent、prompt library，这些内容非常适合作为结构化输入。
